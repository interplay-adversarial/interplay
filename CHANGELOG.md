## [0.4.2] - 2026-10-17

### Added
- `interplay report SOURCE --output NEW_DIRECTORY`: turns retained assessment and runner exports (version-1 and version-2 JSONL, Parquet and Arrow) into a private standalone HTML report plus a matching JSON summary, offline, without provider imports or model calls. Incomplete and error attempts, parent lineage, captured evidence, citation-resolution checks and panel disagreements stay visible; search scores and model judgments remain distinct from independently verified effects. Unknown schemas and ambiguous record bindings are rejected, the source snapshot is bound by SHA-256, captured content is escaped, the report uses no scripts or remote assets, and existing output is never overwritten (roadmap REPORT-01; closes #63).
- `interplay calibration`: a human-reference judge calibration workflow that keeps synthetic design intent separate from human ground truth. `prepare` creates 60 harmless matched cases and two unlabeled review packets; a complete gold reference requires two distinct attested human reviewers per case and a third reviewer for disagreements. An explicit bounded collector retains model replies, and offline scoring reports confusion matrices, false-positive rate, sensitivity, coverage, selective accuracy and nominal Wilson intervals, compares the production plurality/unanimous policies, and reports agreement separately from accuracy (roadmap JUDGE-01; contributes to #60, whose actual human reviews and two-model run remain pending).
- `interplay benchmark`: reproducible fixed-probe comparisons of two explicit model/configuration profiles under equal query, token and timeout caps. A versioned manifest binds the inputs and the executing source; the command runs or imports exact-match observations, retains incomplete outcomes, recovers interrupted journals offline, and writes paired outcome and resource deltas. Usage and cost stay unavailable unless observed, and `accuracy` remains unavailable pending judge calibration (roadmap BENCH-01; closes #61).
- `NeMoGymTarget`, an optional instrumented target in the assessment Python API: each probe/attempt binds to a pinned native SimpleAgent session owned by a trusted per-attempt factory, journals model and tool dispatches, and retains visible trajectories plus a separately observed environment outcome, with cooperative deadlines and incomplete-capture handling for missing, truncated, failed and late observations. Two pinned native Gym revisions are supported (default `f444b80...` and `b454c9a...`), each with its own five-file source manifest; unknown, mixed or modified source is rejected before a session opens, every observation records the selected revision, and isolated native CI jobs run in each revision's environment (roadmap AGENT-01; closes #62, contributes to #64).
- `interplay runner-run` and offline `interplay runner-recover`, schema-version-2 method metadata and private campaign summaries. All six method runners now write to the attempted/observed/final result journals with matching JSONL, Parquet and Arrow exports, and version-1 journals remain readable (#57).
- A prioritized roadmap (`docs/ROADMAP.md`) linking the delivery sequence to the open qualification issues and retaining #24/#25 as research tracks, plus a six-method CLI conformance drill that runs the real CLI in child processes against authenticated loopback endpoints, kills each runner after its response is journaled and before the judge returns, and checks repeated offline recovery, export matching, preserved evidence, role routing and output permissions, with a recovery audit hook that detects even swallowed network attempts (#66; first increment of #59).
- An `extended` CLI conformance profile covering PAIR attacker refinement, two-depth TAP pruning/lineage, three-turn Crescendo context omission, structured GOAT strategy execution, SLIP insertion/refinement and all nine Multimodal PNG transform/control pairs (six actual PNGs per campaign, decoded and compared with retained payload bytes, sizes and digests), with each method also killed at its last judge boundary; both profiles run in CI on Python 3.12 and 3.13 (#67).
- `scripts/garak_cli_conformance.py`: an optional real-Garak loopback drill using one authenticated `test.Blank` generation and Garak's native `any.AnyOutput` detector, verifying the evaluated attempt, response, detector result, report completion and permissions; Python network guards propagate into the scanner process, and receipts bind package/Python versions and parser/harness source digests (#69).
- Tests that pin the new `irr_report` semantics against the real library: no-variation panels report `alpha=None` with a reason, and the interval appears at exactly 5 judged cases.
- `scripts/garak_isolated_audit.py`: audits the full frozen `red-teaming,garak` profile (exported from `uv.lock`) against the PyPI/OSV advisory databases in an ephemeral tool environment, applies explicit version-bound dispositions, and optionally cross-checks an installed venv for lock drift and scans the installed Garak source for the disposed advisory's vulnerable APIs. Fails on any unexpected finding, stale disposition or drift.
- `garak-qualification` CI job in `tests.yml`: installs the frozen isolated profile, runs the audit and the loopback conformance drill on every pull request, push and the weekly schedule; retains the raw audit output and receipts as artifacts.

### Changed
- The judge panel's inter-rater-reliability report now requires `judge-kappa>=0.4.0` (the floor was `>=0.2`; `uv.lock` moves 0.2.1 to 0.4.0, changing only that package). **Behaviour change in `irr_report`:** when every judge gives the same verdict on every case, `irr_report["alpha"]` is now `None` with `irr_report["alpha_not_estimated_reason"] == "no_score_variation"` instead of `1.0`. Judges that never vary have not shown that they agree, and `1.0` read as perfect agreement. A panel with real disagreement is unchanged, and `irr_report` is still `None` with `irr_unavailable_reason` for fewer than two judges or fewer than two judged cases. Code that formats `irr_report["alpha"]` must handle `None`; nothing in this repository does.
- The `garak` extra now requires `garak>=0.17.1` (was `>=0.10.0`). Garak 0.17.1 is the first release that admits patched `datasets>=5.0.1`, so the frozen isolated `red-teaming,garak` profile resolves to datasets 5.1.0 and fsspec 2026.7.0, clearing PYSEC-2026-3716 (datasets 3.6.0) and PYSEC-2026-4217 (fsspec 2025.3.0) (issue #68).
- The NLTK 3.10.3 advisory PYSEC-2026-3740 (CVE-2026-81726) has no patched release yet; the new isolated audit carries an explicit, version-bound disposition for it after verifying the vulnerable APIs are not reachable from Garak 0.17.1.
- Method-runner credential and evidence handling was hardened (#57): explicit credentials are preserved instead of being replaced by ambient provider credentials, separate per-role endpoints/keys and uniquely identified judge members are supported, and known role and provider-fallback keys are redacted, including JSON-escaped reflections, before judging, refinement and retention. Inference requests and awaits are bounded, late results are rejected, aggregate citations are validated, and repeated-model panel members are counted separately while repeated aliases are flagged.
- PAIR migrated to evidence-cited single/panel judging with explicit success and budget handling; its numeric score is now a verdict-derived diagnostic, and its unused final refinements and chain-of-thought requests were removed (#57).
- Garak's unused endpoint routing and placeholder parser were replaced by supervised scanner execution with explicit model/endpoint/report routing and native JSONL stage parsing; the `probe_file` argument is a Garak plugin selector, not an arbitrary JSONL file (#57).
- The judge scorer now accepts bare JSON or one whole-response JSON fence and canonicalizes citation arrays into the existing flat JSON-string field; bounded, redacted raw replies are retained when parsing or finish checks fail. Strict schema validation, supported-evidence checks and incomplete-capture handling remain in force, and surrounding prose, duplicate fields, contradictory objects and malformed citations still cannot establish success (#58).
- The qualification matrix and roadmap now track the bounded live continuation/recovery evidence for PAIR, TAP, Crescendo, GOAT and SLIP, the Gate-side BOUNDARY-01 increment, and both pinned Gym baselines (#67, #69, #70, #75, #76).

### Fixed
- A completed target response could disappear when the judge budget expired: observations are now committed before judging, incomplete trials are retained on judge exhaustion or cancellation, inference stops on storage failure, and immutable fields are bound during recovery (#57).
- Garak 0.17.0 exits successfully with a valid final digest object and no trailing newline, which Interplay treated as a truncated native report. A valid final JSON object is now accepted while torn tails and invalid committed rows remain incomplete or rejected, with regression coverage for completion/digest tails, torn digests and invalid JSON entry types (#69).
- The docs said `irr_report` carries a bootstrapped confidence interval without saying when. judge-kappa computes the interval (`alpha_ci_low`/`alpha_ci_high`) only from 5 judged cases, so a short campaign gets `None` there; `docs/METHODOLOGY.md`, `docs/tools-and-use-cases.md`, `docs/attacks/tap.md` and `JudgePanel.agreement_report()` now say so.
- `tests/test_gym_target.py::test_cooperative_deadline_preserves_tool_effect_and_late_response` raced the rollout budget: the `+2.02` deadline minus the default `observation_seconds=2` left 20 ms for the rollout, so on slower machines the fixture's tool dispatch hit the recording client's deadline guard before recording its effect and the `environment_outcome` assertion failed. The test now uses `observation_seconds=1`, a ~1 s rollout budget that still expires long before the fixture episode's 5 s completion.
- `scripts/smoke_install.py`'s "garak missing gives an install hint" check called `run_garak('http://x/v1', ...)`; `http://` to a non-loopback host is itself rejected by `ModelEndpoint`'s SSRF-style validation, so the check never reached the missing-scanner path and failed with a raw `pydantic` `ValidationError` instead. It now uses `http://localhost/v1`, a URL `ModelEndpoint` accepts, so the check exercises the actual missing-`garak` `RuntimeError`. Separately, that `RuntimeError` named the wrong extra set (`interplay-adversarial[red-teaming,garak]`); `interplay.red_teaming` cannot be imported at all without `red-teaming` already installed, so the only extra still missing at that point is `garak` -- the hint now says `interplay-adversarial[garak]`. Found on 0.4.0's TestPyPI publish, which is abandoned per `docs/RELEASING.md`.
- The same check still didn't reach the missing-scanner path even after the `http://localhost/v1` fix: `run_garak()` raises `garak-api-key-missing` before ever trying to launch the scanner, and the smoke harness's subprocess environment has no `OPENAICOMPATIBLE_API_KEY` set. The check now passes `api_key='synthetic-key'` explicitly. Found on 0.4.1's TestPyPI publish (still 19/20); 0.4.1 is abandoned too, same reason.

## [0.3.1] - 2026-10-15

### Changed
- README.md restructured around "what it is / what it provides / how to start quickly": three capabilities (probe generation, attack methodologies including the judge panel, description-driven assessment) stated once up front instead of scattered across duplicate sections (there were two separate "Attack Methodologies" tables, a "Why" section, and a trailing "Methodology" section repeating the opening paragraph). Pipeline modes, the diverse-dataset helper, available specs and output columns move to new `docs/probe-generation.md`; the redundant detailed attack-methodology table is dropped in favor of `docs/attacks/README.md`; the full environment-variable dump is dropped in favor of `.env.example` (already the single source of truth for those values). README now mentions the judge panel/IRR capability, which it never had before.
- GitHub Actions in all workflows are pinned to full commit SHAs with a version comment (Dependabot keeps them current)
- TAP's `secondary_judge_model` (singular, diagnostic-only: re-judged already-decided branches afterward purely to compute a Cohen's kappa, never affecting the verdict) is replaced by `secondary_judge_models` (plural), shared with every other migrated runner: it now forms a real voting panel with `judge_model`, and agreement comes from those same judge calls instead of a separate re-judging pass. `TapResult.kappa_score`/`kappa_unavailable_reason` are replaced by `irr_report`/`irr_unavailable_reason` (see Added).

### Fixed
- The README restructure above switched several links (`docs/probe-generation.md`, `docs/attacks/README.md`, `docs/assessment.md`, `docs/README.md`, `docs/tools-and-use-cases.md`, `.env.example`, `docs/CONTENT_POLICY.md`, `SECURITY.md`) to relative paths. PyPI does not resolve relative links in a package's long description -- they 404 on the project page -- so every one of them would have been broken on the PyPI listing. Caught by the TestPyPI verification step (`0.3.0` was published there with this defect and never released further); reverted all of them to absolute `https://github.com/.../blob/main/...` URLs, matching the convention the rest of the file already used.
- The publish workflow referenced `astral-sh/setup-uv@v10`, a tag that does not exist (that action publishes exact versions only); it is now pinned to v10.3.0
- `JudgeScorer` (`interplay.red_teaming.transport`) called `any_llm.completion()`, the synchronous API, from inside the running event loop every attack runner executes in; `any_llm` raises `RuntimeError: Cannot use the sync API in an async context` there, which `JudgeScorer.score()`'s own exception handling silently turned into `judge_verdict="inconclusive"` on every call. This made TAP, Crescendo, GOAT, SLIP and Multimodal's evidence-cited judging never actually invoke the judge model in real usage. `JudgeScorer.score()`/`_call()` and `multimodal_runner._run_attempt()` are now `async` and use `any_llm.acompletion()`; the five runners' call sites now `await` them.
- `create_completion_kwargs()` passed a caller-supplied `base_url` straight through as a `base_url` key; `any_llm.completion()`/`acompletion()` only accept `api_base`, so every attacker/judge call that set a custom endpoint (PAIR's own attacker/judge setup, and `JudgeScorer` for every other runner) raised `TypeError: unexpected keyword argument 'base_url'` once it reached the provider SDK. `base_url` is now translated to `api_base`.
- `examples/custom_spec.py` and `examples/diverse_dataset.py` imported `data_designer.types.providers` (removed) and called `DataDesigner(providers=..., model_configs=...)`, both from before a data-designer refactor; neither script could run. Updated to the current API (`data_designer.config.{ModelProvider,ModelConfig}`, `DataDesigner(model_providers=...)`, `builder.add_model_config(...)`, `.preview(...).dataset`, `.create(...).load_dataset()`), and fixed `probe_quality_score` extraction (it is `{"quality": {"score": 0-3, "reasoning": ...}}`, not a flat number). Verified against `scripts/mock_openai.py`.
- `docs/tools-and-use-cases.md` said TAP's judge-agreement (`judge-kappa`) computation "still needs implementation; current return is a placeholder"; it has computed a real two-judge Cohen's kappa since PR #46.
- `examples/integrated_run.py` read `tap_result.kappa_score`, a field the judge-panel change renamed to `irr_report`; the example crashed with `AttributeError` on every run. `docs/METHODOLOGY.md` and `docs/tools-and-use-cases.md` still described TAP's judge agreement as TAP-only and Cohen's-kappa-specific after it became an N-judge-capable, five-runner Krippendorff's-alpha panel.
- `interplay/pipeline.py`'s own `if __name__ == "__main__":` smoke test (`python interplay/pipeline.py` / `python pipeline.py` run directly) had the same pre-refactor `DataDesigner(providers=..., model_configs=...)` call and un-dereferenced `.preview(builder)` (needs `.dataset`) that `examples/custom_spec.py`/`diverse_dataset.py` had; it crashed with `TypeError` on the very first line that touched DataDesigner. Fixed the same way, and verified against `scripts/mock_openai.py` for both a taxonomy mode and a comparison mode.

### Added
- Dependabot keeps the GitHub Actions in the workflows up to date (weekly PRs)
- `hygiene` CI check: every commit in a pull request carries the maintainer's `Signed-off-by`, the PR body ends with it, and no Claude or Hermes session link or id appears in commits, diffs or PR text (bot-authored PRs skip the sign-off)
- `.env.example`, referenced by README.md and AGENTS.md's `cp .env.example .env` setup step but never committed
- `examples/assessment_campaign.py`: a complete, runnable `interplay.assessment` campaign using the built-in `DataDesignerBackend`/`OpenAIEndpointTarget`, in batch and adaptive mode
- `examples/single_attack_runner.py`: run any one of the six attack runners (including Crescendo, GOAT, SLIP and Multimodal, which had no example script) against a target from the command line
- `docs/README.md`: a documentation map and reading-path index; cross-linked from every other doc page and the project README
- `JudgePanel` (`interplay.red_teaming.transport`): a configurable judge panel/jury for TAP, Crescendo, GOAT, SLIP and Multimodal (not PAIR, which isn't migrated to `JudgeScorer`). Pass `secondary_judge_models` alongside `judge_model` to form a panel; `judge_aggregation` (`"majority"` or `"unanimous"`) decides how the judges' verdicts combine into the trial's verdict. Every result gains `irr_report` (a real, N-capable Krippendorff's alpha, via `judge_kappa.KrippendorffAlpha`, with a bootstrapped confidence interval, computed from those same judge calls) and `irr_unavailable_reason`; every trial gains `judge_panel_json` retaining each judge's individual verdict and reasoning, never collapsed away by the aggregation. A single `judge_model` with no secondary models is unaffected -- same `JudgeScorer`, same behavior as before this existed. `examples/single_attack_runner.py` gained `--judge-models`/`--judge-aggregation` to demonstrate it from the command line.

## [0.2.1] - 2026-10-11

### Added
- Dev tooling: `uv sync` now installs pytest, pytest-asyncio, ruff and pip-audit (`dev` dependency group); the `dev` extra carries the same list for pip users
- `interplay probes setup --base-url URL --model NAME [--api-key-env VAR]` defines the model the pipeline uses (data-designer alias `cultural-bias-model`) without storing the key
- `scripts/smoke_install.py` (installs a published or built package in a throwaway directory and exercises it like a new user), `scripts/mock_openai.py` (fake OpenAI-compatible endpoint), an end-to-end test, and `docs/RELEASING.md`
- `scripts/smoke_install.py` inspects the dataset `create` writes for the singapore, sdg-hub-harm and combined modes (all rows kept, every row scored); new sampler and per-mode end-to-end tests
- Publish workflow gate: a release can only reach PyPI if the same version is already on TestPyPI

### Fixed
- `pip install "interplay-adversarial[all]"` could not be installed: Garak pins `cohere`/`mistralai` versions that conflict with `any-llm-sdk[all]`. `all` is now `red-teaming` plus `providers`; install the `garak` extra separately
- The quality judge now scores benign probes too (it used to be skipped with the unused probe column). Before, data-designer's preview table crashed with `'NoneType' object has no attribute 'items'` on most small previews, and benign rows had no quality score. The rubric's top level now applies to both probe types (adversarial probes must still use a named Singapore strategy). Note: this changes the dataset, benign rows now carry a score.
- `sdg-hub-harm` and `combined` modes silently dropped records: the eight harm categories have an empty cultural-context pool and `np.random.choice([])` raised, so every harm row was skipped (`sdg-hub-harm` produced 0 rows). The samplers now fall back when a pool is empty.
- `interplay probes preview` and `create` failed with "No model config with alias 'cultural-bias-model' found" on a fresh install; they now explain how to set the model up
